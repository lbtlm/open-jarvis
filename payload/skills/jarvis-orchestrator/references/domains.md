# Domain acceptance examples

Read only the row relevant to the task. These are examples, not a closed domain list or mandatory teams. Start from the requested deliverable and use a relevant approved specialist. Direct questions and tiny verifiable edits stay with the controller. Model/effort comes from task difficulty and risk, independently of profession; preserve the user's controller and Fast choices.

| Domain | Useful method / skill selection | Acceptance evidence |
| --- | --- | --- |
| Development | User-selected development workflow; frontend design skills for the matching marketing or product UI context; scoped diagnosis/testing when appropriate | Affected behavior, relevant checks, critical diff; rendered UI when appearance matters |
| Writing / novels | Audience, voice, structure and revision; story continuity for fiction; source checks for factual claims | Complete requested text, structural/character consistency, source accuracy where applicable; no mandatory code tests |
| Office | Available document, spreadsheet or presentation skill and actual format tools | Opens in the requested format, checked key figures/formulas and layout; render/preview where the format requires it |
| Video / media | Script, storyboard, visual/audio assets, editing/rendering tools as actually available | Requested stage delivered; a script is not a finished video. Check playback, subtitles, duration and audio when producing a clip |
| Other | Clarify the deliverable, use an existing matching profession or propose a new task-scoped employee | An observable check suited to the user's requested output, not a transplanted software checklist |

A fixed-format cleanup can be Light; a small task with an established method Simple; a bounded article/report/feature with investigation Standard; interdependent plot constraints, conflicting sources, a complex model or consequential behavioral changes Complex. These are reasons to assess, not automatic routing based on file extension. Review triggers still depend on real risk and evidence; a complex story does not automatically need a code reviewer. Choose an independent specialist suited to the review, with real read-only constraints when required.

Skill names on an employee card are suggestions. Honor a relevant user-invoked skill, then discover installed capabilities and read selected instructions. Missing software, account access, rendering or model capability is a concrete blocker for that part; installing Jarvis or seeding a candidate card does not provide it. Any external publication, sending or account action retains its own authorization boundary.
