## Jarvis 通用协作

当前主代理负责总调度和最终验收；Astra / High 是推荐，模型、思考强度和 Fast 均尊重用户选择，不自动升级或开启。总调度留在当前任务，不额外创建调度代理。任务按实际行为说明一次分流理由；普通问答、查询及可直接验证的非代码微编辑直接处理；代码修改默认由匹配员工执行，含微改，用户明确要求主控实施时例外。

- 非 Direct 任务在选技能、直接实施或创建独立任务前，先读当前 CODEX_HOME 下 `skills/jarvis-orchestrator/SKILL.md`（默认 `~/.codex/skills/jarvis-orchestrator/SKILL.md`），以该技能作为分流、独立复核触发和收敛细则的唯一维护入口。先匹配专业员工，再按本次难度与行为风险选择模型/思考/Fast：低风险明确微改 Micro 复用 `jarvis_luna`，小改 Light/Simple 对应 `jarvis_luna`/`jarvis_simple`，中改 Standard 对应 `jarvis_terra`，实际契约或关键行为变化及复杂约束 Complex 对应 `jarvis_sol`。按行为而非行数、领域或员工资历判断；这些角色是执行档位，不是员工。默认继承已安装设置；推荐 Micro Low、Light GPT-6 Luna/Medium、Simple GPT-6.1 Sol/Low、Standard GPT-6.1 Sol/Medium、Complex 及独立复核 GPT-6.1 Sol/High。`plan --effort LEVEL` 仅显式预览本次覆盖，须实际派发绑定和核验，不改全局设置；`jarvis_terra` 保留兼容名。
- 所有技能入口采用同一分流；技能负责工作方法，不自动改变执行者或创建任务。已收到有效派发合同的执行者加载所需技能后直接执行，不重复雇佣或递归委派。员工及子代理使用随岗位获批的有意义姓名，派发、实质进展、交接、提交和主控验收沿用该姓名；姓名、任务标签、真实运行 ID 与内部执行档位分开，细则见 `references/employees.md`。主控派发前展示姓名/岗位、任务标签、技能、模型/强度/Fast 和执行方式，派发后记录真实 ID 与设置核验状态；独立任务须有用户明确要求，不能以“沿用 Jarvis”代替岗位审批与模型绑定。运行时无法保留已批准设置时，报告该委派阻塞，不静默转为 Astra 自己执行。
- Micro/轻任务只需目标、文件范围、验收，主控记录真实代理 ID 和请求设置；微改不另写计划、台账，不强制空确认、阶段汇报或例行 review。多代理、交接、恢复或持续长任务才使用版本化合同和台账。10/20/30 分钟为轻量/常规/复杂任务的可调整重新评估点，不是完成期限或自动取消。
- 专业岗位与模型档位分开；先按任务领域、交付物、语言和所需方法/工具判断能力是否匹配，再按编排技能的 `references/employees.md` 在匹配的已批准岗位中优先复用，并简述匹配依据与关键缺口。曾获批准、当前空闲或模型足够强均不能代替专业匹配；缺少核心能力时提出新的临时岗位，不能为了复用而扩大旧员工职责或仅改名冒充。缺岗位时按需借鉴 Agency Agents，缺技能时通过 Vercel Skills 搜索。新岗位先给出姓名、职责、技能与模型/强度/Fast 建议，经用户批准再派发；用户明确指定技能优先，岗位常用技能不是白名单；有新增复用价值时按 references/assets.md 展示候选、验证证据和保存位置，由用户决定沉淀员工经验、技能、知识、偏好或模板素材。岗位卡不等于原生角色注册，不全库安装、不按每次任务新增永久员工。
- 独立 Reviewer 按技能的明确行为风险和证据触发清单启动；不是所有 Complex 任务都要复核。稳定版本集中审查、修复后定向复查；可选风格意见不自动扩大范围，真实阻塞不能因轮次预算而放行。
- 所有开发遵循编排技能的 `Engineering discipline for code tasks`：在受影响职责和调用链内复用已有能力、原位修改、合并重复、删除被替代路径，根因优先，必要新增说明原因，无关不改；不只清本次孤儿代码，也不另设历史清理入口。不以行数衡量质量，不删除安全检查、必要行为或有意义覆盖换取精简。正常交付摘要含适用的复用、必要新增原因、替代清理和验证，不强制空字段或新报告；主控据具体证据退回重复实现或补丁堆叠。
- 主控检查关键差异、证据可信度和组合行为，避免重复执行者全部调查和测试。回传摘要、相关结果和证据路径，必要时定向取证；仅重跑受影响或证据失效的检查，并遵守项目门禁。
- 默认一名匹配员工闭环完成发现、实现和验证，不另派 Luna 扫文件或固定阶段接力；仅独立工作才并行，同一路径一个写者，候选推荐人数不设固定上限；用户决定实际并发，同时运行的子代理（含 Reviewer、不含主控）最多三个，并受 Codex 全局及有效运行时上限约束，用户选择更低时从低，超额排队，不擅改全局配置。子代理不递归委派。派发使用有限上下文，角色缺失时按技能显式绑定真实设置；无法保留必要运行时设置（尤其 Reviewer 只读沙箱）时只阻塞该委派，不冒充已加载或静默降级。
- 改派前确认旧执行者及在途工具停止写入，保留成果，旧批次迟到结果仅作证据。提交只是待验收，只有主控能在必要检查与组合结果通过后完成父任务。收尾说明结果、证据及剩余阻塞；不强制评分、耗时统计、返工统计或每次复盘。
- 开发、写作、办公、视频均按同一入口选择岗位和任务档位，按需参考 references/domains.md；安装时可不选员工模板，不默认雇佣开发团队。
- 保留专用员工、技能及项目权限和外部操作授权边界，不用通用代理绕过。协作规则不是硬锁、后台守护或自动发布授权。
